Tổng Quan

Dự án chỉ có một schema Room trung tâm, nhưng ở runtime có hai cách lưu trữ: database dùng chung và database riêng theo project. Hai lớp này dùng chung bộ entity, DAO và migration, nên tài liệu này xem chúng là cùng một hệ schema.

Loại ROOMDB File vật lý Ai mở Khi nào dùng Dữ liệu điển hình
Shared Room DB mapsupervision.db DataModule Khi project còn ở LEGACY_SHARED hoặc đang giữ dữ liệu dùng chung. Projects, GIS, progress, photos, notes, tasks, AI cache, reports.
Project-scoped Room DB project.projectDbPath ProjectScopedDatabaseProvider Khi project chuyển sang PROJECT_DB và cần tách dữ liệu sang file riêng. Cùng schema với shared DB, nhưng chỉ chứa dữ liệu của một project.
Điểm vào code Vai trò Ghi chú
MapSupervisionDatabase.kt Khai báo entity, DAO, migration và type converters cho schema chung. Đây là nguồn sự thật chính cho Room schema version 21.
DataModule.kt Cấp shared database mapsupervision.db và các DAO singleton. Đường vào runtime cho storage mode legacy.
ProjectScopedDatabaseProvider.kt Mở database riêng theo project và hydrate dữ liệu legacy khi cần. Đường vào runtime cho storage mode PROJECT_DB.
DbTypeConverters.kt Chuyển đổi enum và list toạ độ sang kiểu lưu trữ của SQLite. Ảnh hưởng trực tiếp đến projects, site_photos và gis_route.
1. LEGACY_SHARED

Shared database

File thật là mapsupervision.db, được tạo trong DataModule. Đây là nơi lưu dữ liệu legacy và cũng là nguồn seed cho project database mới.

2. PROJECT_DB

Project-scoped database

Khi projects.storageMode = PROJECT_DB và projectDbPath có giá trị, ProjectScopedDatabaseProvider sẽ mở một file DB riêng cho project đó.

Dữ liệu legacy được hydrate từ shared DB sang project DB khi project DB còn rỗng. Luồng này đọc dữ liệu theo projectId, gom thành payload, rồi ghi vào database mới trong một transaction. Điểm mấu chốt là cả hai database đều dùng cùng một schema Room, nên migration và entity không bị tách nhánh.

Metadata Dự Án

Bảng projects là trung tâm điều phối storage mode, đường dẫn database và metadata lịch sử.

Trường Ý nghĩa Ghi chú kỹ thuật
metadataVersion Phiên bản metadata của project. Hiện được default về 3, dùng để theo dõi cấu trúc metadata không đồng nhất với Room version.
updatedAtEpochMs Thời điểm cập nhật cuối của metadata project. Migration v10-v11 đã đảm bảo giá trị này được backfill từ createdAtEpochMs nếu còn 0.
storageMode Chế độ lưu trữ dữ liệu của project. Hai giá trị chính: LEGACY_SHARED và PROJECT_DB.
projectDbPath Đường dẫn file database riêng của project. Khi rỗng thì project vẫn ở shared DB; khi có path hợp lệ thì provider mở DB riêng.
projectCode Mã project ở lớp nghiệp vụ. Xuất hiện sau migration v19-v20, phục vụ chuẩn hóa metadata và tương thích dữ liệu cũ.
Bảng projects không chỉ là danh sách project. Nó là điểm quyết định project đó đang sống trong shared DB hay database riêng.

Quan Hệ Schema

Dự án này hầu như không khai báo foreign key vật lý trong Room schema. Quan hệ giữa các bảng chủ yếu được quản lý bằng application logic và index.

Loại quan hệ Đặc điểm Ví dụ trong dự án Ý nghĩa khi đọc schema
Quan hệ vật lý Được biểu diễn bằng primary key, unique index và composite index. projects.id, material_progress unique index trên (projectId, nodeCode, materialName). Đảm bảo tính duy nhất, tăng tốc truy vấn, nhưng không ép ràng buộc foreign key.
Quan hệ logic Ghép dữ liệu bằng các mã nghiệp vụ như projectId, nodeCode, routeCode, objectCode. gis_node.code nối sang node_progress.nodeCode và daily_log.nodeCode. Đây là lớp quan hệ chính của hệ thống, do application logic kiểm soát.
Quan hệ suy diễn Không lưu foreign key trực tiếp mà suy ra từ nội dung CSV hoặc danh sách id. daily_log.linkedPhotoIdsCsv tham chiếu gián tiếp tới site_photos.id. Đòi hỏi code đọc/ghi phải hiểu format lưu trữ của cột.
projects Root metadata, điều phối storage mode và đường dẫn DB.
imported_files Nguồn gốc file nhập, seed cho GIS node/route.
gis_node / gis_route Lớp GIS trung tâm, nối sang tiến độ và ảnh.
daily_log / site_photos / tasks / notes Dữ liệu vận hành hằng ngày theo project và object code.
node_progress / material_progress Tiến độ và vật tư, cùng bám vào gis_node.code.
ai_decision_cache Cache AI theo project/capability/payload hash.
chat_history Lịch sử hội thoại theo project.
report_draft Bản nháp báo cáo, đầu ra cuối của luồng tổng hợp.
Các liên kết logic quan trọng:
  • projects -> imported_files -> gis_node/gis_route
  • projects -> daily_log / site_photos / tasks / notes
  • gis_node.code đối chiếu với node_progress.nodeCode, material_progress.nodeCode, daily_log.nodeCode
  • gis_route.code đối chiếu với daily_log.routeCode, site_photos.matchedRouteCode
  • site_photos.id được tham chiếu gián tiếp từ daily_log.linkedPhotoIdsCsv
Phần lớn quan hệ trong schema này là quan hệ nghiệp vụ, không phải ràng buộc foreign key vật lý trong SQLite schema hiện tại.

Phụ Lục Migration

Phần này chỉ tóm tắt các bước thay đổi có ý nghĩa kiến trúc, không liệt kê toàn bộ SQL.

Version Thay đổi chính Tác động kiến trúc
v9 Baseline schema còn rất nhỏ, làm mốc cho các migration sau. Đặt nền cho schema hiện đại và room_master_table mới.
v10 Mở rộng daily_log và thêm work_categories. Nhật ký thi công bắt đầu có metadata ngày, khối lượng và phân loại công việc.
v11-v12 Thêm metadata cho projects, bao gồm updatedAtEpochMs, storageMode và projectDbPath. Đây là điểm tách shared DB và project DB riêng theo runtime.
v13 Bổ sung metadata GPS cho site_photos. Ảnh hiện trường có thêm trạng thái location và độ chính xác.
v14 Thêm ai_decision_cache. Hệ thống bắt đầu cache kết quả suy luận AI theo payload hash.
v15-v16 Chuẩn hóa lại index và thêm các cột matching/object lookup. Tối ưu các truy vấn theo project, node code và object code.
v17-v18 Thêm batch/matching fields cho daily_log và site_photos, sau đó thêm chat_history. Luồng đối soát ảnh và hội thoại AI trở thành dữ liệu lưu trữ chính thức.
v19 Thêm report_draft. Xuất hiện lớp lưu bản nháp báo cáo trong schema.
v20 Rebuild nhiều bảng để chuẩn hóa schema và index. Cập nhật đồng bộ các bảng cốt lõi, đảm bảo backward compatibility tốt hơn.
v21 Thêm cột gis_route.points. Route GIS có thể lưu chuỗi toạ độ chi tiết thay vì chỉ metadata đầu-cuối.
Tổng kết: schema Room hiện tại là một lớp dữ liệu thống nhất, nhưng runtime đã tiến hóa từ shared-only sang mô hình hybrid shared + per-project.
